ВВЕДЕНИЕ
Актуальность темы. В современных условиях цифровой трансформации экономики особую актуальность приобретают платформенные решения, объединяющие различные категории участников бизнес-процессов. Развитие стартап-экосистемы, рост венчурных инвестиций и популярность криптовалютных активов создают потребность в специализированных инструментах для эффективного взаимодействия предпринимателей, инвесторов и трейдеров.
Согласно данным исследований, более 70% стартапов испытывают трудности с поиском инвесторов из-за отсутствия централизованных платформ для презентации проектов. Инвесторы, в свою очередь, сталкиваются с проблемой оценки перспективности стартапов и отсутствием инструментов для комплексного анализа. Бизнесмены нуждаются в актуальной рыночной аналитике и экономических индикаторах для принятия обоснованных решений. Крипто трейдеры требуют удобных инструментов для отслеживания динамики криптовалютного рынка и анализа трендов.
Существующие решения, как правило, ориентированы на одну целевую аудиторию и не обеспечивают комплексного подхода к взаимодействию всех участников бизнес-сообщества. Отсутствие единой экосистемы приводит к фрагментации информации, усложнению коммуникации и снижению эффективности бизнес-процессов.
Разработка web-приложения "BusinessUnion" направлена на решение указанных проблем путем создания единой платформы, объединяющей стартаперов, инвесторов, бизнесменов и криптотрейдеров. Особую актуальность приобретает разработка клиентской части приложения, обеспечивающей удобный и интуитивно понятный интерфейс для различных категорий пользователей с учетом их специфических потребностей.
Целью курсового проекта является разработка клиентской части web-приложения "BusinessUnion" для объединения стартаперов, инвесторов, бизнесменов и криптотрейдеров на единой платформе.
Для достижения поставленной цели необходимо решить следующие задачи:
- Исследовать и проанализировать проблемы проектирования и разработки клиентской части web-приложений для бизнес-платформ, а также современные технологии и фреймворки для создания интерактивных пользовательских интерфейсов.
- Определить основные функциональные требования и характеристики разрабатываемой системы для различных типов пользователей.
- Спроектировать и реализовать архитектуру клиентской части приложения, включая структуру компонентов, маршрутизацию, персонализированные дашборды для четырех типов пользователей и ключевые функциональные модули.
- Интегрировать клиентскую часть с серверным API и внешними сервисами, а также провести тестирование.
Объектом курсового проекта является проектирование и разработка клиентской части web-приложения для бизнес-платформы.
Предметом исследования является процесс разработки клиентской части информационной системы "BusinessUnion" с использованием технологий Vue.js 3, Vuetify, Pinia, Vue Router и библиотек визуализации данных Chart.js и ECharts.

Во второй главе представлен процесс проектирования и разработки клиентской части приложения "BusinessUnion", описана архитектура системы, структура компонентов, реализация основных модулей для различных типов пользователей, интеграция с серверным API и внешними сервисами, а также результаты тестирования системы.

ГЛАВА 1. ТЕОРЕТИЧЕСКИЕ АСПЕКТЫ РАЗРАБОТКИ КЛИЕНТСКОЙ ЧАСТИ WEB-ПРИЛОЖЕНИЯ "BUSINESSUNION"
1.1. Запуск проекта
Запуск проекта по разработке клиентской части web-приложения "BusinessUnion" включает анализ требований, планирование архитектуры и выбор технологического стека. Основной идеей является создание единой экосистемы для взаимодействия четырех категорий пользователей: стартаперов, инвесторов, бизнесменов и криптотрейдеров, каждая из которых имеет уникальные требования к функциональности.
При запуске проекта проведен анализ существующих решений: AngelList, LinkedIn, TradingView и специализированных венчурных платформ. Анализ показал, что существующие решения фокусируются на отдельных сегментах и не предоставляют комплексного инструментария для всех участников бизнес-процессов. Ключевым преимуществом разрабатываемого приложения является интеграция функциональности для различных типов пользователей в рамках единой платформы.
В качестве основного фреймворка выбран Vue.js 3, обеспечивающий высокую производительность и реактивность. Для пользовательского интерфейса используется Vuetify с компонентами Material Design. Управление состоянием реализовано через Pinia, маршрутизация — через Vue Router с поддержкой защищенных маршрутов. Для визуализации данных интегрированы Chart.js и ECharts, взаимодействие с API организовано через Axios.
Архитектура построена на принципах компонентного подхода с разделением на уровни: views, components, services, stores и utils. Такая организация обеспечивает масштабируемость и упрощает поддержку приложения.
Система аутентификации реализована с использованием JWT-токенов. Роутер проверяет права доступа перед переходом на защищенные страницы. Модуль мессенджера обеспечивает личные и групповые чаты с отображением статуса прочтения. Модуль сообществ позволяет создавать публикации и реагировать на контент. Образовательный модуль предоставляет каталог курсов с рекомендациями на основе роли пользователя. Модуль событий позволяет управлять мероприятиями и регистрироваться на участие.
Организована система контроля версий с использованием Git. Разработан процесс сборки с использованием Docker-контейнеров и Nginx. Настроена интеграция с серверным API на NestJS и внешними сервисами: CoinGecko для криптовалют, LunarCrush для социальных метрик, Alpha Vantage для фондовых рынков, Exchange Rate API для валют.
Реализована система кэширования данных на клиентской стороне. Применены техники ленивой загрузки компонентов и виртуализации списков для оптимизации производительности. Разработана адаптивная верстка с использованием возможностей Vuetify для корректного отображения на различных устройствах.
1.1.1. Стадии развития проекта
Разработка клиентской части web-приложения "BusinessUnion" осуществляется поэтапно в соответствии с современными методологиями управления IT-проектами. Жизненный цикл проекта включает последовательность взаимосвязанных стадий с определенными целями и результатами.
Первая стадия — инициация, на которой формируется видение приложения. Проводится анализ рынка бизнес-платформ, изучаются потребности целевой аудитории. Формулируется бизнес-идея объединения стартаперов, инвесторов, бизнесменов и криптотрейдеров на единой платформе. Определяются ключевые ценностные предложения для каждой категории пользователей. Результатом является концепция проекта с целями и функциональными требованиями.
Вторая стадия — планирование, в рамках которого разрабатывается детальный план реализации. Осуществляется выбор технологического стека: Vue.js 3 как основной фреймворк, Vuetify для UI-компонентов, Pinia для управления состоянием. Определяется структура проекта с разделением на компоненты, сервисы, хранилища и утилиты. Разрабатывается план интеграции с серверным API и внешними сервисами. Результатом является техническое задание с описанием архитектуры и плана работ.
Третья стадия — проектирование интерфейсов и архитектуры. Создаются прототипы для различных типов пользователей: макеты главной страницы, страниц аутентификации, персонализированных дашбордов, каталога стартапов, мессенджера, сообществ, образовательных курсов и событий. Разрабатывается дизайн-система с цветовой палитрой, типографикой и стилями компонентов. Проектируется структура хранилищ состояния и схемы взаимодействия с API. Результатом являются макеты страниц и документация по архитектуре.
Четвертая стадия — непосредственная разработка. Инициализируется проект Vue.js, устанавливаются зависимости: Vuetify, Pinia, Vue Router, Axios, Chart.js, ECharts. Реализуется базовая структура с маршрутизацией и навигацией. Разрабатываются переиспользуемые UI-компоненты. Создается модуль аутентификации с защитой маршрутов. Реализуются персонализированные дашборды: для стартаперов — метрики проекта и информация об инвестициях; для инвесторов — портфель и аналитика доходности; для бизнесменов — рыночная аналитика и экономические индикаторы; для криптотрейдеров — портфель криптовалют и обзор рынка. Разрабатываются модули каталога стартапов, мессенджера, сообществ, образования и событий. Интегрируются библиотеки визуализации данных. Настраивается взаимодействие с серверным API через Axios и интеграция с внешними API: CoinGecko, LunarCrush, Alpha Vantage, Exchange Rate API. Результатом является функционирующее приложение со всеми модулями.
Пятая стадия — тестирование для выявления ошибок и проверки соответствия требованиям. Проводится модульное тестирование компонентов, интеграционное тестирование взаимодействия модулей, функциональное тестирование пользовательских сценариев. Выполняется тестирование производительности с оптимизацией кода, кросс-браузерное тестирование в Chrome, Firefox, Safari и Edge, тестирование адаптивности на различных устройствах и тестирование безопасности. Результатом является стабильное приложение с подтвержденным соответствием требованиям.
1.1.2. Описание ценности проекта и аналогов проекта
Проект "BusinessUnion" представляет собой инновационную бизнес-платформу, основная ценность которой заключается в создании единой экосистемы для взаимодействия четырех ключевых категорий участников бизнес-процессов: стартаперов, инвесторов, бизнесменов и криптотрейдеров. Уникальность проекта состоит в комплексном подходе к решению задач каждой целевой аудитории в рамках одного приложения, что создает синергетический эффект от взаимодействия различных участников.
Для стартаперов платформа предоставляет централизованное пространство для презентации своих проектов широкой аудитории потенциальных инвесторов. Основатели стартапов получают возможность создавать детальные описания проектов с указанием стадии развития, необходимого объема инвестиций, ожидаемой доходности и дополнительной информации о команде, бизнес-плане и достижениях. Система позволяет управлять проектами, отслеживать прогресс реализации, фиксировать ключевые вехи развития и обновлять информацию для инвесторов. 
Для инвесторов платформа создает значительную ценность через предоставление доступа к верифицированной базе стартапов с возможностью детального анализа и оценки перспективности проектов. Реализованы инструменты фильтрации и поиска стартапов по различным критериям, включая отрасль, стадию развития, требуемый объем инвестиций и ожидаемую доходность. Интеграция с искусственным интеллектом Yandex Cloud позволяет проводить автоматический анализ стартапов с оценкой рисков и потенциала роста. Прямая коммуникация с основателями стартапов через мессенджер обеспечивает оперативное получение информации и возможность влиять на развитие проектов. Снижение инвестиционных рисков достигается за счет комплексного анализа проектов, доступа к финансовой отчетности и возможности изучения отзывов других инвесторов.
Для бизнесменов платформа предоставляет комплексные инструменты рыночной аналитики и мониторинга экономических показателей. Реализован дашборд с актуальными данными о курсах валют, фондовых индексах, макроэкономических показателях и венчурной активности. Интеграция с внешними API обеспечивает получение данных в реальном времени из надежных источников, включая World Bank для макроэкономических показателей, Alpha Vantage для информации о фондовых рынках и Exchange Rate API для курсов валют. Бизнесмены получают доступ к аналитике трендов различных отраслей, прогнозам развития рынков и информации о венчурных сделках. 
Для криптотрейдеров платформа предоставляет комплексный инструментарий для анализа криптовалютного рынка и принятия торговых решений. Реализован криптотрекер с данными по топовым криптовалютам, включая текущие цены, изменения за различные периоды, объемы торгов и рыночную капитализацию. Интеграция с CoinGecko API обеспечивает получение актуальных данных по более чем 100 криптовалютам. Интеграция с LunarCrush API предоставляет социальные метрики криптовалют, включая упоминания в социальных сетях, активность сообщества и влияние на рынок. 
Анализ существующих аналогов на рынке показывает, что большинство платформ фокусируются на решении задач одной целевой аудитории. 1.1.3. Распределение ролей
Разработка клиентской части web-приложения "BusinessUnion" осуществляется командой из трёх специалистов, каждый из которых отвечает за определённую область проекта. Чёткое распределение ролей обеспечивает эффективную организацию рабочего процесса и высокое качество конечного продукта.
Роль frontend-разработчика является ключевой и включает полный цикл разработки клиентской части приложения. В обязанности входит проектирование архитектуры клиентского приложения с определением структуры компонентов, организации хранилищ состояния и системы маршрутизации. Осуществляется выбор технологического стека с использованием Vue.js 3 в качестве основного фреймворка, Vuetify для создания пользовательского интерфейса, Pinia для управления состоянием и дополнительных библиотек для визуализации данных. Разрабатывается структура проекта с организацией папок и файлов в соответствии с best practices для Vue.js приложений.
Создаются переиспользуемые UI-компоненты, включая кнопки, формы ввода, модальные окна, карточки и таблицы, которые используются во всём приложении для обеспечения консистентности дизайна. Реализуются все страницы приложения: главная страница, страницы регистрации и входа, персонализированные дашборды для различных типов пользователей, каталог стартапов, страницы создания и редактирования проектов, мессенджер, сообщества, образовательные курсы и события.
Разрабатывается система маршрутизации с использованием Vue Router, включая настройку защищённых маршрутов и проверку авторизации пользователей. Создаются хранилища состояния с использованием Pinia для управления данными пользователя, проектов, инвестиций, сообщений и аналитики. Реализуется взаимодействие с серверным API через сервисы с использованием Axios, включая добавление токенов аутентификации к запросам и обработку ошибок.
Интегрируются библиотеки визуализации данных Chart.js и ECharts для создания интерактивных графиков в аналитических модулях. Осуществляется интеграция с внешними API для получения данных о криптовалютах, фондовых рынках, курсах валют и экономических показателях. Разрабатывается адаптивная вёрстка с использованием возможностей Vuetify для корректного отображения на различных устройствах. Проводится оптимизация производительности с применением ленивой загрузки компонентов, виртуализации списков и кэширования данных.
Роль backend-разработчика включает создание серверной части приложения, которая обеспечивает обработку бизнес-логики, хранение данных и предоставление API для клиентской части. Backend-разработчик отвечает за проектирование архитектуры серверного приложения с использованием фреймворка NestJS, который обеспечивает модульную структуру и поддержку TypeScript.
Разрабатывается структура базы данных MySQL с определением таблиц для пользователей, проектов, инвестиций, сообщений, чатов, сообществ, постов и событий. Создаются модели данных с использованием TypeORM для объектно-реляционного отображения. Реализуются контроллеры для обработки HTTP-запросов, включая эндпоинты для аутентификации, управления проектами, инвестициями, сообщениями и сообществами. Разрабатываются сервисы для реализации бизнес-логики, включая валидацию данных и интеграцию с внешними API.
Создаётся система аутентификации и авторизации с использованием JWT-токенов, включая генерацию токенов при входе и проверку при доступе к защищённым ресурсам. Реализуются guards для защиты эндпоинтов и проверки прав доступа на основе ролей пользователей. Интегрируются внешние API: CoinGecko для криптовалют, LunarCrush для социальных метрик, Alpha Vantage для фондовых рынков, Exchange Rate API для курсов валют и World Bank API для макроэкономических показателей. Разрабатывается модуль интеграции с Yandex Cloud AI для анализа стартапов с использованием искусственного интеллекта.
Создаётся система обработки и хранения файлов для загрузки изображений и документов. Реализуется система миграций базы данных для управления изменениями схемы. Настраивается Docker-конфигурация для контейнеризации приложения. Разрабатывается API-документация с использованием Swagger.
Роль тестировщика включает обеспечение качества приложения через систематическое тестирование функциональности и выявление ошибок. Тестировщик отвечает за разработку тестовой документации, включая тест-планы, тест-кейсы и чек-листы для различных модулей.
Проводится функциональное тестирование пользовательских сценариев: регистрация пользователей с различными ролями, вход в систему, восстановление пароля. Проверяется функциональность создания и редактирования проектов, включая заполнение полей и загрузку изображений. Тестируется каталог стартапов с проверкой фильтрации, сортировки и поиска. Проверяется функционал инвестирования, управление портфелем и отображение аналитики. Тестируется мессенджер с проверкой отправки сообщений, создания чатов и отображения статуса прочтения. Проверяется функциональность сообществ: создание, публикация постов, комментирование и реакции.
Проводится тестирование интеграции с внешними API с проверкой корректности данных о криптовалютах, фондовых рынках и курсах валют. Осуществляется тестирование производительности с измерением времени загрузки страниц и отзывчивости интерфейса. Проводится кросс-браузерное тестирование в Chrome, Firefox, Safari и Edge. Осуществляется тестирование адаптивности на различных устройствах: десктопах, планшетах и смартфонах.
Проводится регрессионное тестирование после внесения изменений для проверки существующей функциональности. Выполняется тестирование безопасности с проверкой защиты от XSS-атак, CSRF-атак и SQL-инъекций. Тестировщик документирует выявленные ошибки с описанием шагов воспроизведения и приложением скриншотов. Создаются отчёты о тестировании с указанием количества тест-кейсов и выявленных ошибок.
Взаимодействие между членами команды организовано через регулярные встречи для обсуждения прогресса и планирования работ. Frontend-разработчик и backend-разработчик согласовывают структуру API, форматы запросов и ответов. Frontend-разработчик предоставляет тестировщику информацию о реализованной функциональности. Тестировщик сообщает разработчикам о выявленных ошибках. Используется система контроля версий Git для управления кодом и система управления задачами для планирования и отслеживания прогресса.
1.2. Исследование по проработке концепции проекта
Проработка концепции проекта "BusinessUnion" включала комплексное исследование рынка бизнес-платформ, анализ потребностей целевой аудитории и изучение современных технологий разработки web-приложений. Данное исследование позволило сформировать четкое видение проекта и определить оптимальные технологические решения для реализации.
Первым этапом исследования стал анализ существующих решений на рынке. Изучены платформы для стартапов и инвесторов, такие как AngelList и Crunchbase, которые предоставляют возможности для презентации проектов и поиска финансирования, но фокусируются исключительно на взаимодействии стартапов и инвесторов. Проанализированы профессиональные социальные сети, включая LinkedIn, обеспечивающие нетворкинг, но не включающие специализированный функционал для инвестиций и аналитики. Изучены платформы для трейдеров, такие как TradingView, предоставляющие мощные инструменты технического анализа криптовалют, но не ориентированные на стартапы и инвесторов. Результаты анализа показали отсутствие комплексного решения, объединяющего функциональность для всех четырех категорий пользователей, что подтвердило актуальность разработки проекта.
Вторым этапом стало изучение потребностей целевой аудитории. Для стартаперов выявлены ключевые проблемы, включающие сложность поиска инвесторов, необходимость использования множества различных сервисов и недостаток инструментов для презентации проектов. Для инвесторов определены потребности в доступе к качественной базе стартапов, инструментах анализа и оценки проектов, удобном управлении портфелем инвестиций. Для бизнесменов выявлены потребности в актуальной рыночной аналитике, мониторинге экономических показателей и возможности нетворкинга. Для криптотрейдеров определены потребности в комплексном криптотрекере, инструментах технического анализа и социальных метриках рынка.
Третьим этапом стало изучение современных технологий разработки web-приложений. Проанализированы популярные JavaScript-фреймворки, включая React, Vue.js и Angular. React требует дополнительных библиотек для маршрутизации и управления состоянием, что усложняет начальную настройку. Angular имеет более сложную архитектуру и крутую кривую обучения. Vue.js 3 выбран благодаря оптимальному балансу между функциональностью, производительностью и простотой разработки, предоставляя улучшенную производительность, Composition API и встроенную поддержку TypeScript.
Четвертым этапом стало проектирование архитектуры клиентской части. Разработана модульная архитектура с разделением на компоненты представления, переиспользуемые UI-компоненты, сервисы для работы с API, хранилища состояния и утилиты. Спроектирована система маршрутизации с публичными маршрутами, защищенными маршрутами и маршрутами с проверкой ролей. Реализована система навигационных guards для проверки авторизации и прав доступа. Спроектирована структура хранилищ состояния для управления данными пользователя, проектов, инвестиций, сообщений, сообществ и аналитики.
Пятым этапом стало изучение подходов к интеграции с внешними API. Для получения данных о криптовалютах выбран CoinGecko API благодаря бесплатному доступу и широкому покрытию. Для социальных метрик выбран LunarCrush API. Для данных о фондовых рынках выбран Alpha Vantage API. Для курсов валют выбран Exchange Rate API. Для макроэкономических показателей выбран World Bank API, предоставляющий открытый доступ к данным об инфляции, безработице и других экономических индикаторах.
Шестым этапом стало изучение подходов к обеспечению безопасности. Выбран подход с использованием JWT-токенов для аутентификации благодаря простоте реализации и масштабируемости. Определены методы защиты от XSS-атак через санитизацию пользовательского ввода, от CSRF-атак через использование токенов и проверку origin запросов. Разработаны best practices для безопасного хранения токенов с использованием httpOnly cookies для refresh-токенов и localStorage для access-токенов с коротким временем жизни.
Седьмым этапом стало изучение подходов к оптимизации производительности. Определены техники ленивой загрузки компонентов и маршрутов для сокращения времени первоначальной загрузки. Изучены методы оптимизации изображений и кэширования данных на клиентской стороне. Проанализированы техники виртуализации длинных списков для эффективного отображения больших объемов данных.
Восьмым этапом стало изучение подходов к обеспечению адаптивности интерфейса. Проанализированы принципы responsive-дизайна и возможности Vuetify для создания адаптивных интерфейсов. Определены контрольные точки для мобильных устройств, планшетов, десктопов и широких экранов.
Результаты проведенного исследования позволили сформировать четкую концепцию проекта как комплексной бизнес-платформы, определить уникальное ценностное предложение, выбрать оптимальный технологический стек и спроектировать модульную архитектуру клиентской части. Проработаны подходы к интеграции с внешними API, обеспечению безопасности, оптимизации производительности и развертыванию приложения, что создало прочную основу для успешной реализации проекта.

ГЛАВА 2. ПРОЕКТИРОВАНИЕ И РАЗРАБОТКА WEB-ПРИЛОЖЕНИЯ "BUSINESSUNION"
2.1. Проектирование технического задания для web-приложения «BusinessUnion»
Техническое задание на разработку клиентской части web-приложения "BusinessUnion" определяет требования к функциональности, архитектуре и технической реализации системы. Документ служит основой для проектирования и разработки приложения, обеспечивая единое понимание целей и задач проекта всеми участниками команды.
Web-приложение "BusinessUnion" представляет собой комплексную бизнес-платформу, предназначенную для объединения четырех категорий пользователей: стартаперов, инвесторов, бизнесменов и криптотрейдеров. Основная цель проекта заключается в создании единой экосистемы для эффективного взаимодействия участников бизнес-процессов, предоставления специализированных инструментов для каждой категории пользователей и обеспечения доступа к актуальной информации и аналитике. Клиентская часть приложения реализуется как одностраничное приложение с использованием современных web-технологий, обеспечивающих высокую производительность, отзывчивость интерфейса и удобство использования.
Функциональные требования определяют возможности системы и действия, которые пользователи могут выполнять в приложении. Модуль аутентификации и управления пользователями должен обеспечивать регистрацию новых пользователей с выбором типа роли, валидацию введенных данных с проверкой уникальности email, вход в систему по email и паролю, восстановление забытого пароля, просмотр и редактирование профиля с возможностью загрузки аватара и указания контактной информации.
Для стартаперов реализуется функционал создания проектов с указанием названия, описания, категории, стадии развития, требуемого объема инвестиций и ожидаемой доходности. Система поддерживает загрузку изображений проекта, бизнес-плана и презентации, добавление информации о команде и достижениях. Дашборд стартапера отображает метрики проектов, информацию о полученных инвестициях и рекомендации по развитию.
Для инвесторов предоставляется каталог стартапов с возможностью фильтрации по различным критериям, детальный просмотр информации о проектах, функционал создания инвестиций и управления портфелем. Дашборд инвестора включает аналитику портфеля, информацию о новых проектах, историю транзакций и прогнозы доходности.
Для бизнесменов реализуется дашборд с актуальной рыночной аналитикой, включающей курсы валют, фондовые индексы, макроэкономические показатели и венчурную аналитику. Система обеспечивает визуализацию данных через интерактивные графики с возможностью выбора периода отображения и сравнения показателей.
Для криптотрейдеров предоставляется криптотрекер с отображением топовых криптовалют, их цен, изменений и объемов торгов. Система включает детальную информацию о каждой криптовалюте с историческими графиками, социальными метриками и новостями. Дашборд отображает индекс страха и жадности рынка, тепловую карту изменений цен и прогнозы движения.
Модуль мессенджера обеспечивает создание личных и групповых чатов, отправку текстовых сообщений, отображение списка чатов с последними сообщениями и счетчиками непрочитанных. Модуль сообществ предоставляет возможность создания сообществ по интересам, публикации постов, комментирования и реакций. Модуль образования отображает каталог курсов с фильтрацией и рекомендациями. Модуль событий предоставляет календарь мероприятий с возможностью регистрации на участие.
Нефункциональные требования определяют качественные характеристики системы. Требования к производительности включают время загрузки главной страницы не более 3 секунд, время отклика интерфейса не более 200 миллисекунд, плавную анимацию с частотой 60 кадров в секунду. Приложение должно эффективно работать с большими объемами данных, используя техники виртуализации и ленивой загрузки.
Требования к безопасности включают использование HTTPS для всех соединений, защиту от XSS и CSRF атак, безопасное хранение токенов аутентификации, валидацию данных на клиентской и серверной стороне. Требования к удобству использования включают интуитивно понятный интерфейс с четкой навигацией, консистентный дизайн, информативные сообщения об ошибках, подтверждение критических действий. Интерфейс должен быть адаптивным и корректно отображаться на устройствах с различными размерами экрана от 320px до 2560px.
Требования к совместимости включают поддержку современных версий браузеров Chrome, Firefox, Safari и Edge, работу на операционных системах Windows, macOS, Linux, iOS и Android. Требования к масштабируемости включают модульную архитектуру, позволяющую добавлять новые функции без изменения существующего кода, возможность горизонтального масштабирования и эффективное кэширование данных.
Технические требования определяют технологии и инструменты разработки. В качестве основного фреймворка используется Vue.js версии 3, обеспечивающий реактивность и компонентный подход. Для создания интерфейса применяется библиотека Vuetify версии 3 с компонентами Material Design. Управление состоянием реализуется через Pinia, маршрутизация через Vue Router версии 4. Для взаимодействия с API используется Axios, для визуализации данных - Chart.js и ECharts.
Структура проекта организована с разделением на папки components для переиспользуемых компонентов, views для страниц, services для работы с API, stores для хранилищ состояния, utils для вспомогательных функций, assets для статических ресурсов. Система сборки основана на Vite, для контроля качества кода используется ESLint, для форматирования - Prettier.
Развертывание приложения осуществляется с использованием Docker-контейнеров. Создается многоэтапный Dockerfile с этапом сборки приложения и этапом продакшена с Nginx для обслуживания статических файлов. Конфигурация Nginx включает настройку сжатия gzip, кэширования статических ресурсов и проксирования запросов к API.
Таким образом, техническое задание определяет полный набор требований к клиентской части web-приложения "BusinessUnion", включая функциональные возможности для различных типов пользователей, нефункциональные характеристики производительности и безопасности, а также технические решения для реализации системы, что обеспечивает основу для проектирования архитектуры и разработки приложения.
2.2. Описание процесса разработки web-приложения «BusinessUnion»
Процесс разработки клиентской части web-приложения "BusinessUnion" осуществлялся в соответствии с итеративной методологией, позволяющей постепенно наращивать функциональность системы и оперативно вносить изменения на основе обратной связи. Разработка велась параллельно с созданием серверной части, что обеспечивало своевременную интеграцию компонентов и раннее выявление проблем взаимодействия.
Начальным этапом разработки стала инициализация проекта и настройка окружения разработки. Создан новый проект Vue.js с использованием официального инструмента создания проектов Vite, обеспечивающего быструю разработку и оптимизированную сборку. Выполнена установка необходимых зависимостей, включая Vuetify для создания пользовательского интерфейса, Pinia для управления состоянием приложения, Vue Router для организации маршрутизации, Axios для работы с HTTP-запросами, Chart.js и ECharts для визуализации данных, date-fns для работы с датами. Настроена конфигурация проекта с определением алиасов путей для упрощения импортов, настройкой переменных окружения для различных режимов работы, конфигурацией сборки для оптимизации производительности.
Организована структура проекта в соответствии с принципами модульности и разделения ответственности. Создана папка components для хранения переиспользуемых UI-компонентов, которые могут использоваться на различных страницах приложения. Папка views содержит компоненты страниц, соответствующие маршрутам приложения. Папка services включает модули для работы с API, инкапсулирующие логику взаимодействия с сервером. Папка stores содержит хранилища состояния Pinia для управления данными приложения. Папка utils включает вспомогательные функции для форматирования данных, валидации и других общих операций. Папка assets содержит статические ресурсы, включая изображения, стили и шрифты. Папка router включает конфигурацию маршрутизации приложения. Такая организация обеспечивает логическое разделение кода, упрощает навигацию по проекту и облегчает поддержку.
Следующим этапом стала разработка базовой структуры приложения и системы маршрутизации. Создан главный компонент App.vue, служащий корневым элементом приложения и содержащий общую структуру с навигацией и областью для отображения страниц. Реализована система навигации с использованием компонентов Vuetify, включающая верхнюю панель приложения с логотипом, меню навигации и элементами управления пользователем, боковую панель для мобильных устройств с адаптивным отображением. Настроена маршрутизация с использованием Vue Router, определены маршруты для всех основных страниц приложения, включая главную страницу, страницы регистрации и входа, дашборды для различных типов пользователей, каталог стартапов, страницы создания и редактирования проектов, мессенджер, сообщества, образовательные курсы и события. Реализована система защиты маршрутов с использованием navigation guards, проверяющих авторизацию пользователя перед доступом к защищенным страницам и перенаправляющих неавторизованных пользователей на страницу входа с сохранением запрошенного URL для последующего перенаправления после успешной авторизации.
Разработаны переиспользуемые UI-компоненты, формирующие основу пользовательского интерфейса приложения. Создан компонент BaseButton для кнопок с различными вариантами стилей, размеров и состояний, включая основные кнопки, вторичные кнопки, кнопки с иконками, кнопки загрузки. Реализован компонент BaseInput для полей ввода с поддержкой различных типов данных, валидации, отображения ошибок и подсказок. Разработан компонент BaseCard для карточек с единообразным стилем, используемых для отображения проектов, пользователей и другой информации. Создан компонент BaseModal для модальных окон с настраиваемым содержимым, используемых для подтверждения действий, отображения форм и детальной информации. Реализован компонент BaseTable для таблиц с поддержкой сортировки, фильтрации и пагинации. Разработан компонент BaseChart для графиков с использованием Chart.js, предоставляющий единообразный интерфейс для различных типов визуализаций. Все компоненты разработаны с учетом принципов переиспользования, настраиваемости через props и событий для взаимодействия с родительскими компонентами.
Реализован модуль аутентификации и управления пользователями. Создана страница регистрации с формой, включающей поля для ввода имени, фамилии, email, пароля и выбора типа роли пользователя. Реализована валидация полей с проверкой формата email, сложности пароля, заполнения обязательных полей. Разработана страница входа с формой для ввода email и пароля, опцией запоминания пользователя, ссылкой на восстановление пароля. Создан сервис authService для работы с API аутентификации, включающий методы для регистрации, входа, выхода, восстановления пароля и обновления токена. Реализовано хранилище userStore с использованием Pinia для управления состоянием пользователя, включающее данные текущего пользователя, статус авторизации, токены доступа и обновления, методы для входа, выхода и загрузки профиля. Настроена автоматическая проверка срока действия токена и его обновление при необходимости. Реализована страница профиля пользователя с отображением личной информации, возможностью редактирования данных, загрузки аватара и изменения пароля.
Разработаны персонализированные дашборды для каждого типа пользователей. Для стартаперов создан дашборд StartupFounderDashboard, отображающий метрики проектов с количеством просмотров, заинтересованных инвесторов и полученных предложений, информацию об инвестициях с текущим объемом привлеченных средств и прогрессом относительно цели, список активных проектов с возможностью быстрого перехода к редактированию, рекомендации по развитию проектов на основе анализа активности. Для инвесторов реализован дашборд InvestorDashboard, включающий обзор портфеля инвестиций с общей стоимостью, количеством активных инвестиций и средней доходностью, список активных сделок с информацией о проектах и статусе инвестиций, аналитику доходности с графиками изменения стоимости портфеля за различные периоды, последние транзакции с детальной информацией о каждой операции. Для криптотрейдеров разработан дашборд CryptoTraderDashboard, отображающий портфель криптовалют с текущей стоимостью и изменениями, активные позиции с информацией о точках входа, текущих ценах и прибыли/убытках, торговую статистику с количеством сделок и процентом успешных, обзор рынка с топовыми криптовалютами и их динамикой.

Добавлено отображение индекса страха и жадности рынка с историческими данными и интерпретацией значений. Реализована тепловая карта изменений цен криптовалют для визуализации динамики рынка. Навигационная структура включает боковую панель для десктопных устройств и выдвижное меню для мобильных, обеспечивая быстрый доступ ко всем разделам приложения. 2.4. Реализация базы данных web-приложения «BusinessUnion»
База данных web-приложения "BusinessUnion" реализована с использованием реляционной системы управления базами данных MySQL версии 8.0, обеспечивающей надежное хранение данных, поддержку транзакций и высокую производительность при работе с большими объемами информации. Для взаимодействия с базой данных на стороне серверного приложения применяется ORM-библиотека TypeORM, предоставляющая объектно-ориентированный подход к работе с данными и автоматическую генерацию SQL-запросов на основе определенных сущностей.
Структура базы данных спроектирована в соответствии с принципами нормализации для исключения избыточности данных и обеспечения целостности информации. Центральной сущностью системы является таблица пользователей (users), содержащая основную информацию об участниках платформы: идентификатор, имя, фамилию, отчество, email, хешированный пароль и тип пользователя. Поле userType реализовано как перечисление (enum) с возможными значениями startup_founder, investor, businessman и crypto_trader, определяющими роль пользователя в системе и доступный ему функционал. Пароли пользователей хешируются с использованием алгоритма bcrypt с фактором сложности 10, обеспечивая защиту от несанкционированного доступа даже при компрометации базы данных.
Расширенная информация о пользователях хранится в связанной таблице профилей (profiles), имеющей отношение один-к-одному с таблицей users. Таблица profiles содержит поля для аватара пользователя, биографии, контактной информации (телефон, город, регион), ссылок на социальные сети, информации об образовании и профессиональной квалификации, специализации и интересов. Для инвесторов дополнительно хранятся данные о размере инвестиций и предпочитаемых отраслях. Такое разделение данных на основную и расширенную информацию позволяет оптимизировать запросы, загружая профильные данные только при необходимости.
Модуль проектов реализован через таблицу projects, содержащую информацию о стартапах: название, описание, категорию, стадию развития, требуемый объем инвестиций, ожидаемую доходность, изображение проекта, ссылки на бизнес-план и презентацию. Каждый проект связан с пользователем-создателем через внешний ключ authorId, обеспечивающий каскадное удаление проектов при удалении пользователя. Категории проектов вынесены в отдельную таблицу project_categories для обеспечения консистентности данных и возможности централизованного управления списком категорий. Таблица project_team_member реализует систему управления командами проектов, связывая пользователей с проектами и определяя их роли (team_lead, admin, member) через поле role типа enum. Таблица project_tasks обеспечивает функционал управления задачами внутри проектов с полями для названия, описания, статуса, приоритета, исполнителя и сроков выполнения.
Система инвестиций реализована через таблицу investments, связывающую инвесторов с проектами и содержащую информацию об объеме инвестиций, дате вложения, статусе инвестиции и ожидаемой доходности. Установлены внешние ключи на таблицы users (поле investorId) и projects (поле projectId), обеспечивающие ссылочную целостность данных.
Модуль мессенджера построен на трех взаимосвязанных таблицах. Таблица chats содержит информацию о чатах с полями для названия, типа (personal или group) и идентификатора связанного проекта для командных чатов. Таблица chat_users реализует связь многие-ко-многим между пользователями и чатами, позволяя одному пользователю участвовать в нескольких чатах и одному чату включать множество участников. Таблица messages хранит сообщения с полями для содержимого, идентификаторов чата и отправителя, временной метки отправки и статуса прочтения. Индексы на полях chatId и senderId обеспечивают быструю выборку сообщений для отображения истории переписки.
Функционал сообществ реализован через набор связанных таблиц. Таблица community_category содержит категории сообществ с названием, иконкой и флагом активности. Таблица community хранит информацию о сообществах: название, описание, изображение, флаг приватности, идентификаторы категории и создателя. Таблица community_member реализует связь пользователей с сообществами, включая поле isModerator для определения прав модерации. Таблица community_post содержит посты в сообществах с полями для содержимого, изображения, счетчиков лайков, комментариев и просмотров. Таблица community_post_reaction реализует систему реакций на посты, связывая пользователей с постами и типом реакции.
Модуль событий представлен таблицей events, содержащей информацию о мероприятиях: название, описание, дату и время начала и окончания, место проведения, тип события, максимальное количество участников и идентификатор организатора. Связанная таблица event_participants реализует регистрацию пользователей на события со статусом участия (registered, attended, cancelled).
Образовательный модуль включает таблицы education_platform для хранения информации об образовательных платформах и education_course для курсов с полями названия, описания, платформы, URL, длительности, уровня сложности, категории и рейтинга.
Для обеспечения миграционной стратегии развития базы данных используется механизм миграций TypeORM, позволяющий версионировать изменения схемы и применять их последовательно. Миграции хранятся в директории migrations и выполняются автоматически при развертывании новых версий приложения. Реализованы миграции для создания всех основных таблиц, добавления полей контактной информации и социальных ссылок, создания таблиц событий, образовательных материалов, сообществ и задач проектов.
Настройка базы данных осуществляется через файл конфигурации data-source.ts, определяющий параметры подключения: хост, порт, имя пользователя, пароль и название базы данных, получаемые из переменных окружения. Параметр synchronize установлен в true для режима разработки, обеспечивая автоматическую синхронизацию схемы базы данных с определенными сущностями, но должен быть отключен в продакшн-окружении для предотвращения случайной потери данных. Параметр logging позволяет включать вывод SQL-запросов в консоль для отладки.
Для обеспечения производительности на часто запрашиваемых полях созданы индексы: на email в таблице users для быстрого поиска пользователей при аутентификации, на authorId в таблице projects для выборки проектов конкретного пользователя, на chatId и senderId в таблице messages для оптимизации загрузки истории сообщений. Установлены ограничения уникальности на поле email в таблице users для предотвращения регистрации дубликатов.
Конфигурация MySQL включает настройки для оптимальной работы: кодировка utf8mb4 для поддержки полного набора Unicode-символов включая эмодзи, collation utf8mb4_unicode_ci для корректной сортировки и сравнения строк, увеличенное значение max_connections до 1000 для поддержки большого количества одновременных подключений, размер innodb_buffer_pool_size установлен в 1GB для кэширования данных в памяти и ускорения операций чтения.
Резервное копирование базы данных осуществляется через утилиту mysqldump с созданием полных дампов структуры и данных. Реализованы скрипты автоматического резервного копирования с сжатием результирующих файлов и ротацией старых копий. Восстановление данных производится путем импорта SQL-дампа в чистую базу данных.
Таким образом, реализованная структура базы данных обеспечивает надежное хранение всей необходимой информации приложения, поддерживает целостность данных через систему внешних ключей и ограничений, оптимизирована для быстрого выполнения запросов через индексы и настройки СУБД, а также предоставляет механизмы миграций для безопасного развития схемы данных в процессе эволюции приложения.

2.5. Разработка бизнес-логики web-приложения «BusinessUnion»
Бизнес-логика web-приложения "BusinessUnion" реализована на серверной части с использованием фреймворка NestJS, обеспечивающего модульную архитектуру, внедрение зависимостей и декларативный подход к построению API. Приложение организовано в виде набора функциональных модулей, каждый из которых инкапсулирует логику работы с определенной предметной областью и предоставляет REST API endpoints для взаимодействия с клиентской частью.
Модуль аутентификации и авторизации (AuthModule) реализует систему безопасности приложения на основе JWT-токенов. Сервис AuthService содержит методы register и login для регистрации новых пользователей и входа в систему. При регистрации выполняется проверка уникальности email через обращение к UsersService, хеширование пароля с использованием библиотеки bcrypt с фактором сложности 10, создание записи пользователя в базе данных и автоматическое создание связанного профиля. Метод login осуществляет валидацию учетных данных путем сравнения введенного пароля с хешированным значением из базы данных, проверку соответствия типа пользователя при необходимости и генерацию JWT-токена при успешной аутентификации. Токен содержит payload с email пользователя, идентификатором в поле sub и типом пользователя, подписывается секретным ключом из переменных окружения и имеет срок действия, настраиваемый в конфигурации. Для защиты маршрутов используется JwtAuthGuard, проверяющий наличие и валидность токена в заголовке Authorization запроса. Стратегия JwtStrategy извлекает и валидирует токен, декодирует payload и прикрепляет информацию о пользователе к объекту request для использования в контроллерах и сервисах.
Модуль управления пользователями (UsersModule) обеспечивает функционал работы с профилями участников платформы. Сервис UsersService предоставляет методы для создания пользователей с автоматической генерацией профиля, поиска по идентификатору и email, получения списка всех пользователей, обновления профильной информации и поиска пользователей по запросу. Метод createProfile создает запись профиля, связанную с пользователем, если она отсутствует. Метод updateProfile обрабатывает обновление данных профиля с предварительной валидацией и преобразованием типов данных, особенно для числовых полей типа investmentSize. Метод searchUsers реализует поиск пользователей по частичному совпадению в полях имени, фамилии или email с использованием оператора LIKE и ограничением результатов до 10 записей для оптимизации производительности. Контроллер UsersController предоставляет endpoints для получения профиля текущего пользователя, обновления профильной информации, поиска пользователей и получения информации о конкретном пользователе по идентификатору.
Модуль проектов (ProjectsModule) реализует функционал управления стартапами и командами. Сервис ProjectsService содержит методы create для создания проектов с обработкой загружаемых файлов (изображения, бизнес-планы, презентации), сохранением их в файловую систему и записью путей в базу данных. При создании проекта автоматически добавляется запись в таблицу project_team_member, назначающая создателя тимлидом команды. Метод findAll возвращает список всех проектов с загрузкой связанных данных автора через relations. Метод findByAuthor реализует поиск проектов, где пользователь является тимлидом, с предварительной инициализацией команд для старых проектов через метод initializeTeamForOldProjects. Метод getTeamMembers возвращает список участников команды проекта с проверкой прав доступа, автоматическим добавлением автора как тимлида при отсутствии и удалением дубликатов участников. Реализована логика обеспечения единственности тимлида в команде с автоматическим понижением лишних тимлидов до роли администратора. Метод addTeamMember добавляет нового участника в команду с проверкой прав текущего пользователя, валидацией типа добавляемого пользователя и автоматическим добавлением в командный чат проекта. Метод updateTeamMemberRole изменяет роль участника с обработкой назначения нового тимлида и понижения предыдущего. Метод removeTeamMember исключает участника из команды с проверкой, что не удаляется тимлид. Методы update и remove обеспечивают редактирование и удаление проектов с обработкой загруженных файлов.
Модуль сообществ (CommunitiesModule) предоставляет функционал социального взаимодействия. Сервис CommunitiesService реализует методы create для создания сообществ с автоматическим добавлением создателя как участника, findAll для получения списка сообществ с загрузкой связанных данных, joinCommunity для вступления в сообщество с проверкой существующего членства, leaveCommunity для выхода с валидацией, что создатель не может покинуть сообщество. Метод createPost создает посты в сообществах с проверкой, что только создатель сообщества может публиковать контент. Метод getCommunityPosts возвращает ленту постов с загрузкой информации об авторах и реакциях, добавляя флаг isLiked для текущего пользователя. Метод togglePostReaction реализует переключение лайков с автоматическим обновлением счетчика. Метод getCategories возвращает список активных категорий с автоматической инициализацией при первом запросе через onModuleInit. Метод getCommunityNotifications генерирует персонализированные уведомления о новых постах и реакциях на посты пользователя за последние 7 дней.
Модуль криптотрекинга (CryptoTrackerModule) интегрирует внешние API для получения данных о криптовалютах. Сервис CryptoTrackerService инициализирует HTTP-клиенты для CoinGecko и LunarCrush API с настройкой таймаутов и заголовков аутентификации. Метод getTopCoins получает список топовых криптовалют с текущими ценами, изменениями, объемами и капитализацией, фильтруя некорректные данные и преобразуя значения в числовой формат. Метод getSocialMetrics запрашивает социальные метрики из LunarCrush API, включая galaxy score, alt rank, social volume и influence. Метод getMarketHeatmap комбинирует данные о ценах и социальных метриках для построения тепловой карты рынка с категоризацией монет по капитализации. Метод getTrustIndex вычисляет персональный индекс доверия монете на основе волатильности, объема торгов, социального скора и новостного фона с применением взвешенных коэффициентов. Метод getChartData получает исторические OHLC данные для построения графиков цен. Метод getBTCDominance возвращает долю Bitcoin в общей капитализации рынка с вычислением изменения за 24 часа. Метод getFearGreedIndex получает индекс страха и жадности из Alternative.me API с кэшированием результата на 15 минут для снижения количества запросов. Метод getTokenomics возвращает данные о токеномике монеты, включая общее и циркулирующее предложение, максимальное предложение и полностью разводненную оценку. Методы getAnomalies, getPriceForecast, getScamCheck и getInvestorCases реализуют аналитические функции на основе алгоритмов обработки рыночных данных.
Модуль рыночной аналитики (MarketAnalyticsModule) агрегирует данные из различных источников. Сервис MarketAnalyticsService содержит методы getCryptoMarketData для получения данных о криптовалютах из CoinGecko API с fallback на моковые данные при ошибках, getStockMarketData для получения информации о фондовых рынках из Alpha Vantage API, getMarketNews для загрузки новостей. Метод getMarketSummary объединяет данные из всех источников в единый ответ. Сервис BusinessAnalyticsService реализует специализированную аналитику для бизнесменов с методами getStartupStatistics для получения статистики стартапов из базы данных, getTopStartups для выборки проектов с наивысшим ROI, getInvestmentTrends для анализа динамики инвестиций, getCategoryDistribution для распределения проектов по категориям, getRiskAnalysis для оценки рисков и getMarketForecast для прогнозирования роста рынка.
Модуль мессенджера (ChatModule) обеспечивает коммуникацию между пользователями. Сервис ChatService предоставляет методы createChat для создания новых чатов с указанием типа и участников, findUserChats для получения списка чатов пользователя с загрузкой последних сообщений и счетчиков непрочитанных, getChatMessages для получения истории сообщений чата с пагинацией. Сервис MessageService реализует методы sendMessage для отправки сообщений с валидацией принадлежности пользователя к чату, markAsRead для отметки сообщений прочитанными и getUnreadCount для подсчета непрочитанных сообщений.
Модуль образования (EducationModule) управляет образовательным контентом. Сервис EducationService содержит методы getCourses для получения списка курсов с фильтрацией по платформе и категории, getPlatforms для получения списка образовательных платформ, getRecommendedCourses для генерации персонализированных рекомендаций на основе роли пользователя и его интересов.
Модуль событий (EventsModule) управляет мероприятиями. Сервис EventsService реализует методы create для создания событий, findAll для получения списка с фильтрацией по дате и типу, registerForEvent для регистрации пользователя на участие с проверкой лимита участников, getUserEvents для получения событий, на которые зарегистрирован пользователь.
Все сервисы используют внедрение зависимостей через декоратор @Injectable, получая доступ к репозиториям TypeORM через @InjectRepository для работы с базой данных. Контроллеры используют декораторы @Controller для определения базового пути, @Get, @Post, @Patch, @Delete для HTTP-методов, @Body для извлечения тела запроса, @Param для параметров пути, @Query для параметров запроса, @UseGuards для применения guards аутентификации и авторизации. Применяется декоратор @ApiTags для группировки endpoints в Swagger-документации и @ApiBearerAuth для указания требования JWT-токена.
Валидация входных данных осуществляется через class-validator с использованием DTO-классов, содержащих декораторы @IsString, @IsEmail, @IsNumber, @IsEnum, @IsOptional для определения правил валидации. ValidationPipe автоматически проверяет соответствие данных схеме и возвращает понятные сообщения об ошибках при нарушении правил.
Обработка ошибок реализована через систему исключений NestJS с использованием классов NotFoundException, BadRequestException, ForbiddenException, UnauthorizedException, InternalServerErrorException для различных типов ошибок. Все методы сервисов обернуты в try-catch блоки для перехвата исключений и логирования ошибок через встроенный Logger.
Таким образом, разработанная бизнес-логика обеспечивает полный функционал приложения через модульную архитектуру, реализует безопасное взаимодействие с данными через валидацию и авторизацию, интегрирует внешние API для получения актуальной рыночной информации и предоставляет REST API для взаимодействия с клиентской частью приложения.

2.6. Руководство пользователя web-приложения «BusinessUnion»
Руководство пользователя web-приложения "BusinessUnion" предназначено для ознакомления с функциональными возможностями платформы и последовательностью действий при работе с системой. Приложение доступно через веб-браузер по адресу развернутого сервера и не требует установки дополнительного программного обеспечения на устройство пользователя.
Для начала работы с платформой необходимо пройти процедуру регистрации. На главной странице приложения расположена кнопка "Начать бесплатно" или "Создать аккаунт", при нажатии на которую открывается форма регистрации. Пользователь заполняет обязательные поля: имя, фамилию, адрес электронной почты, пароль и подтверждение пароля. Поле отчества является необязательным. Важным этапом регистрации является выбор типа пользователя из выпадающего списка: стартапер для основателей проектов, инвестор для лиц, заинтересованных в инвестировании, бизнесмен для предпринимателей, нуждающихся в аналитике рынка, или крипто-трейдер для участников криптовалютного рынка. Выбор типа определяет набор доступных функций и персонализацию интерфейса. В поле интересов можно указать области профессиональных интересов для получения релевантных рекомендаций. Перед завершением регистрации необходимо ознакомиться и согласиться с пользовательским соглашением и политикой конфиденциальности, установив соответствующий флажок. После нажатия кнопки "Зарегистрироваться" система проверяет корректность введенных данных, уникальность email и создает учетную запись с автоматическим входом в систему.
Для входа в систему зарегистрированным пользователям необходимо перейти на страницу входа, нажав кнопку "Вход" в верхней панели навигации или ссылку "Войти в систему" на главной странице. В форме входа вводится адрес электронной почты и пароль, указанные при регистрации. При успешной аутентификации пользователь перенаправляется на главный дашборд приложения, где отображается персонализированная информация в зависимости от типа учетной записи.
Главный дашборд представляет собой центральную панель управления, содержащую актуальную информацию и быстрый доступ к основным функциям. В верхней части дашборда отображается приветственное сообщение с именем пользователя, его ролью и ключевыми метриками активности. Боковая навигационная панель обеспечивает доступ ко всем разделам приложения: главная страница, мессенджер, поиск людей, новости и события, образование, сообщества, аналитика рынка, каталог стартапов, аналитика стартапов, бизнес-аналитика и крипто-трекер. Основная область дашборда содержит виджеты с курсами валют, последними сообщениями, информацией о сообществах, образовательными курсами, рыночной аналитикой и новостями. Каждый виджет предоставляет краткую информацию и ссылку для перехода к полному разделу.
Для редактирования профиля пользователь нажимает кнопку "Профиль" в нижней части боковой панели навигации. На странице профиля отображается текущая информация пользователя, включая аватар, имя, роль, контактные данные и дополнительные сведения. Кнопка "Редактировать" в верхней части страницы открывает режим редактирования, позволяющий изменить личные данные, загрузить или изменить аватар, добавить информацию о профессиональной деятельности, образовании, специализации и интересах, указать ссылки на профили в социальных сетях. После внесения изменений необходимо нажать кнопку "Сохранить" для применения обновлений.
Модуль мессенджера обеспечивает коммуникацию между участниками платформы. При переходе в раздел "Мессенджер" отображается список активных чатов с превью последних сообщений и временем отправки. Непрочитанные сообщения выделяются счетчиком. Для начала новой переписки необходимо найти пользователя через раздел "Люди", открыть его профиль и нажать кнопку "Написать". Автоматически создается личный чат, и пользователь перенаправляется в окно переписки. В окне чата отображается история сообщений с указанием отправителя и времени. Для отправки сообщения необходимо ввести текст в поле внизу экрана и нажать кнопку отправки или клавишу Enter. Сообщения доставляются в реальном времени, и интерфейс автоматически обновляется при получении новых сообщений.
Раздел "Люди" предназначен для поиска партнеров, инвесторов или участников команды. Страница содержит строку поиска для ввода имени, фамилии или email пользователя, а также фильтры для отбора по типу пользователя, отрасли и локации. Результаты поиска отображаются в виде карточек с аватаром, именем, ролью и контактной информацией. Кнопка "Написать" открывает чат с выбранным пользователем, а кнопка "Профиль" позволяет просмотреть детальную информацию о нем.
Модуль "Новости и события" информирует о актуальных мероприятиях и новостях бизнес-сообщества. Раздел разделен на две части: последние новости и ближайшие события. Новости отображаются в виде карточек с заголовком, кратким описанием и датой публикации. События представлены с указанием даты, времени, названия, формата проведения и локации. Для регистрации на мероприятие необходимо нажать кнопку "Зарегистрироваться" на карточке события. Календарь в правой части экрана визуализирует предстоящие события с возможностью добавления новых мероприятий через кнопку "Добавить событие".
Раздел "Образование" предоставляет доступ к каталогу обучающих курсов. Курсы организованы по категориям и могут быть отфильтрованы по целевой аудитории через вкладки в верхней части страницы. Каждая карточка курса содержит название, описание, информацию о платформе, длительности, уровне сложности, рейтинге и стоимости. Кнопка "Подробнее" открывает детальную информацию о курсе, а кнопка "Перейти к курсу" перенаправляет на внешнюю образовательную платформу для прохождения обучения.
Модуль "Сообщества" позволяет объединяться с единомышленниками по профессиональным интересам. Страница отображает список доступных сообществ с возможностью фильтрации по категориям: бизнес, инвесторы, крипто и стартапы. Для создания нового сообщества необходимо нажать кнопку "Создать сообщество", заполнить форму с названием, описанием, выбрать категорию и настройки приватности, загрузить обложку. Для вступления в существующее сообщество нужно открыть его карточку и нажать кнопку "Посмотреть", затем "Присоединиться". Участники сообщества могут просматривать ленту постов, публиковать собственные посты с текстом и изображениями, ставить лайки и комментировать публикации других участников.
Раздел "Аналитика рынка" предоставляет комплексную информацию о состоянии глобальных рынков. Страница содержит блоки с макроэкономическими показателями различных стран, включая инфляцию, ставки центральных банков, безработицу и доверие потребителей. Раздел фондовых индексов отображает текущие значения основных биржевых индексов с возможностью фильтрации по регионам. Блок венчурной активности показывает метрики инвестиционного рынка, включая общую активность, рост раундов и IPO тренды. Данные обновляются автоматически с заданной периодичностью.
Каталог стартапов доступен через раздел "Каталог стартапов" и предназначен для поиска инвестиционных проектов. Страница содержит фильтры для отбора проектов по типу, отрасли и локации, а также строку поиска. Проекты отображаются в виде карточек с изображением, названием, отраслью, кратким описанием, требуемым объемом инвестиций и ожидаемой доходностью. import { defineStore } from 'pinia';
import authService from '@/services/auth.service';

export const useUserStore = defineStore('user', {
  state: () => ({
    user: null,
    isAuthenticated: false,
    loading: false,
    error: null
  }),

  getters: {
    currentUser: (state) => state.user,
    userType: (state) => state.user?.userType,
    isStartupFounder: (state) => state.user?.userType === 'startup_founder',
    isInvestor: (state) => state.user?.userType === 'investor',
    isBusinessman: (state) => state.user?.userType === 'businessman',
    isCryptoTrader: (state) => state.user?.userType === 'crypto_trader'
  },

  actions: {
    async login(credentials) {
      try {
        this.loading = true;
        this.error = null;
        const response = await authService.login(credentials.email, credentials.password);
        
        if (response.access_token) {
          localStorage.setItem('token', response.access_token);
          this.user = response.user;
          this.isAuthenticated = true;
        }
        
        return response;
      } catch (error) {
        this.error = error.response?.data?.message || 'Ошибка входа';
        throw error;
      } finally {
        this.loading = false;
      }
    },

    async register(userData) {
      try {
        this.loading = true;
        this.error = null;
        const response = await authService.register(userData);
        
        if (response.access_token) {
          localStorage.setItem('token', response.access_token);
          this.user = response.user;
          this.isAuthenticated = true;
        }
        
        return response;
      } catch (error) {
        this.error = error.response?.data?.message || 'Ошибка регистрации';
        throw error;
      } finally {
        this.loading = false;
      }
    },

    async loadUser() {
      const token = localStorage.getItem('token');
      if (!token) {
        this.clearUserData();
        return;
      }

      try {
        this.loading = true;
        const response = await authService.getProfile();
        this.user = response.data;
        this.isAuthenticated = true;
      } catch (error) {
        console.error('Ошибка загрузки профиля:', error);
        this.clearUserData();
      } finally {
        this.loading = false;
      }
    },

    logout() {
      authService.logout();
      this.clearUserData();
    },

    clearUserData() {
      this.user = null;
      this.isAuthenticated = false;
      this.error = null;
      localStorage.removeItem('token');
    },

    hasRole(role) {
      return this.user?.userType === role;
    }
  }
});

import axios from 'axios';

const API_URL = process.env.VUE_APP_API_URL || '/api';

class AuthService {
  async login(email, password) {
    try {
      const response = await axios.post(`${API_URL}/auth/login`, {
        email,
        password
      });
      
      if (response.data.access_token) {
        localStorage.setItem('token', response.data.access_token);
      }
      
      return response.data;
    } catch (error) {
      console.error('Login error:', error);
      throw error;
    }
  }

  async register(userData) {
    try {
      const response = await axios.post(`${API_URL}/auth/register`, {
        email: userData.email,
        password: userData.password,
        firstName: userData.firstName,
        lastName: userData.lastName,
        middleName: userData.middleName,
        userType: userData.userType,
        interests: userData.interests
      });
      
      if (response.data.access_token) {
        localStorage.setItem('token', response.data.access_token);
      }
      
      return response.data;
    } catch (error) {
      console.error('Registration error:', error);
      throw error;
    }
  }

  async getProfile() {
    const token = localStorage.getItem('token');
    
    if (!token) {
      throw new Error('No token found');
    }
    
    try {
      const response = await axios.get(`${API_URL}/users/profile`, {
        headers: {
          Authorization: `Bearer ${token}`
        }
      });
      
      return response;
    } catch (error) {
      console.error('Get profile error:', error);
      throw error;
    }
  }

  logout() {
    localStorage.removeItem('token');
  }

  getCurrentToken() {
    return localStorage.getItem('token');
  }
}

export default new AuthService();

          return;
        }
      }
      
      next();
      return;
    }
    
    if (to.matched.some(record => record.meta.guest)) {
      if ((userStore.isAuthenticated || token) && from.name !== null && from.path !== to.path) {
        next('/dashboard');
        return;
      }
      next();
      return;
    }
    
    next();
  } catch (error) {
    console.error('Ошибка в роутере:', error);
    next();
  }
});

export default router;
