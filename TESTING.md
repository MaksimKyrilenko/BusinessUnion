# Руководство по тестированию BusinessUnion API

Этот документ описывает как использовать тесты для функционального и производительностного тестирования API.

## 🚀 Быстрый старт

### Шаг 1: Запустите только Backend
```bash
cd backend
npm run start:dev
```

### Шаг 2: В другом терминале запустите тесты
```bash
# Из корневой директории проекта
npm run test:functional    # Функциональные тесты
npm run test:performance  # Тесты производительности
```

**Важно:** Frontend запускать НЕ нужно! Тесты работают напрямую с API.

## Функциональное тестирование

Функциональное тестирование проверяет корректность работы всех основных endpoints API.

### Что тестируется:

- ✅ Базовые endpoints (health check)
- ✅ Аутентификация (регистрация, вход)
- ✅ Управление пользователями (профиль, поиск)
- ✅ Проекты (список, создание, получение)
- ✅ События
- ✅ Образование (курсы, платформы)
- ✅ Финансовая аналитика
- ✅ Категории проектов

### Особенности:

- Автоматическое создание тестового пользователя
- Проверка статус-кодов ответов
- Валидация структуры данных
- Измерение времени ответа для каждого запроса
- Детальное логирование результатов

## Тестирование производительности

Тестирование производительности проводит нагрузочное тестирование API для оценки:

- ⚡ Время ответа (среднее, минимальное, максимальное)
- 📊 Процентили (P95, P99)
- 🚀 Пропускная способность (запросов в секунду)
- ✅ Процент успешных запросов
- 📈 Стабильность под нагрузкой

### Параметры тестирования:

- **Параллельных запросов**: 10 (по умолчанию)
- **Запросов на endpoint**: 50 (по умолчанию)
- **Таймаут**: 30000 мс (30 секунд)

## Настройка

### Переменные окружения

Вы можете настроить параметры тестирования через переменные окружения:

```bash
# Базовый URL API (по умолчанию: http://localhost:3001/api)
export API_URL=http://localhost:3001/api

# Для тестов производительности:
export CONCURRENT_REQUESTS=10        # Количество параллельных запросов
export REQUESTS_PER_ENDPOINT=50      # Количество запросов на endpoint
export TIMEOUT_MS=30000              # Таймаут в миллисекундах
```

### Windows PowerShell:

```powershell
$env:API_URL="http://localhost:3001/api"
$env:CONCURRENT_REQUESTS="10"
$env:REQUESTS_PER_ENDPOINT="50"
```

### Windows CMD:

```cmd
set API_URL=http://localhost:3001/api
set CONCURRENT_REQUESTS=10
set REQUESTS_PER_ENDPOINT=50
```

## Запуск тестов

### ⚠️ Важно: Что нужно запустить?

**✅ Backend сервер ОБЯЗАТЕЛЕН** - тесты делают HTTP запросы к API  
**❌ Frontend НЕ нужен** - тесты работают напрямую с API, минуя frontend

### Предварительные требования

1. **Запустите backend сервер:**
   ```bash
   cd backend
   npm run start:dev
   ```
   Сервер должен работать на порту 3001 (по умолчанию)

2. Убедитесь, что база данных настроена и доступна

3. Установлены все зависимости в корне проекта: `npm install`

4. Тесты автоматически проверят доступность сервера перед запуском

### Запуск функциональных тестов

```bash
npm run test:functional
```

или напрямую:

```bash
node functional-tests.js
```

### Запуск тестов производительности

```bash
npm run test:performance
```

или напрямую:

```bash
node performance-tests.js
```

### Запуск всех тестов

```bash
npm run test:all
```

## Интерпретация результатов

### Функциональное тестирование

- **PASS** ✅ - Тест пройден успешно
- **FAIL** ❌ - Тест провален (проверьте детали в файле результатов)
- **SKIP** ⊘ - Тест пропущен (обычно из-за отсутствия токена)

### Тестирование производительности

#### Время ответа:

- **< 100 мс** - Отлично ⭐⭐⭐
- **100-500 мс** - Хорошо ⭐⭐
- **500-1000 мс** - Приемлемо ⭐
- **> 1000 мс** - Требует оптимизации ⚠️

#### Процент успешности:

- **> 99%** - Отлично ✅
- **95-99%** - Хорошо ⚠️
- **< 95%** - Требует внимания ❌

#### Запросов в секунду:

- Зависит от сложности endpoint
- Для простых GET запросов ожидается > 50 req/s
- Для сложных запросов с БД ожидается > 10 req/s

## Устранение неполадок

### Ошибка: "ECONNREFUSED"

**Причина**: Backend сервер не запущен или недоступен

**Решение**: 
1. Убедитесь, что backend запущен: `cd backend && npm run start:dev`
2. Проверьте, что сервер работает на порту 3001
3. Проверьте переменную окружения `API_URL`

### Ошибка: "Request timeout"

**Причина**: Сервер не успевает обработать запросы

**Решение**:
1. Увеличьте `TIMEOUT_MS`
2. Уменьшите `CONCURRENT_REQUESTS` и `REQUESTS_PER_ENDPOINT`
3. Проверьте производительность сервера и базы данных

### Ошибка: "401 Unauthorized"

**Причина**: Проблемы с аутентификацией

**Решение**:
1. Проверьте настройки JWT в backend
2. Убедитесь, что база данных содержит пользователей
3. Проверьте логи backend для деталей

### Тесты проходят, но результаты не сохраняются

**Причина**: Проблемы с правами доступа к файлам

**Решение**:
1. Проверьте права на запись в директорию проекта
2. Убедитесь, что файлы не открыты в другом приложении

## Дополнительные возможности

### Интеграция с CI/CD

Тесты можно интегрировать в CI/CD пайплайны:

```yaml
# Пример для GitHub Actions
- name: Run Functional Tests
  run: npm run test:functional
  
- name: Run Performance Tests
  run: npm run test:performance
```

### Автоматический анализ результатов

Вы можете создать скрипт для автоматического анализа результатов:

```javascript
const functionalResults = require('./functional-test-results.json');
const performanceResults = require('./performance-test-results.json');

// Анализ и генерация отчета
```

## Поддержка

При возникновении проблем:

1. Проверьте логи backend сервера
2. Проверьте файлы результатов тестирования
3. Убедитесь, что все зависимости установлены
4. Проверьте настройки базы данных и окружения
